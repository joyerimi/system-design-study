## 포스팅 전송(팬아웃) 서비스

- 어떤 사용자의 새 포스팅을 친구 관계에 있는 모든 사용자에게 전달

**팬아웃 방법 2가지**

- 쓰기 시점에 팬아웃(**fanout on write**, push 모델)
- 읽기 시점에 팬아웃(**fanout on read**, pull 모델)

### 쓰기 시점 팬아웃

- 포스팅을 기록하는 시점에 뉴스 피드를 갱신

장점

- 뉴스 피드가 실시간으로 갱신되며 친구 목록에 있는 사용자에게 즉시 전송
- 새 포스팅이 기록되는 순간에 뉴스피드가 갱신되기 때문에 뉴스 피드를 읽는 데 드는 시간이 짧아짐

단점

- 친구가 많은 사용자의 경우 모든 친구의 뉴스 피드를 갱신하는 데 많은 시간이 소요될 수 있음(**저스틴 비버 문제, 핫키 문제**)
- 서비스를 사용하지 않는 사용자의 피드까지 갱신해야 하므로 컴퓨팅 자원이 낭비됨

### 읽기 시점 팬아웃

- 피드를 읽어야 하는 시점에 뉴스 피드를 갱신(**= on-demand**)

장점

- 비활성화된 사용자, 거의 로그인하지 않는 사용자의 경우 이 모델이 유리함
- 데이터를 친구 각각에게 푸시하는 작업이 필요 없으므로 핫키 문제도 생기지 않음

단점

- 뉴스 피드를 읽는 데 많은 시간이 소요될 수 있음
